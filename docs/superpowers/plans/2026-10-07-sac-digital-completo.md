## Restrições globais
Sem envios, chamadas, campanhas ou alterações de registros de clientes em produção durante testes. Preservar dados, permissões e alterações recentes. Migrações aditivas. Contratos ambíguos devem falhar com diagnóstico, sem trocar rotas/tokens silenciosamente. Não expor credenciais ao navegador. Última instrução do usuário autoriza implementar o escopo inteiro. Usar fixtures, teste real de validações, build CRM final único.

## Task 1: catálogo compartilhado e contratos (root)
Criar supabase/functions/_shared/sac-contracts.mjs com SAC_ENDPOINTS (92 fichas auditadas), campos de formulários, buildSacRequest(id, values), mediaLimit(type), canonicalJson, response helpers. Importável por Node, Edge e Vite. Fichas usam id e campos com nomes publicados; somente catálogo resolve URL. Campos dinâmicos de mensagens, edição, filtros e campanhas têm validação dedicada. Mídia Gestor: imagem 1MB, áudio 3MB, vídeo/arquivo 5MB. Testes Node red/green sobre rotas, parâmetros, rejeição de chaves não permitidas, corpo de observação, caption operacional, validação campanha e URL sem data URL. Plano inclui dependências externas na matriz, sem afirmar verificação viva.

## Task 2: backend e atendimento
Arquivos próprios: sac-digital-api/index.ts; _shared/sac-gateway.ts e testes; migrations/20261007140000_sac_digital_delivery_sessions.sql. Criar gateway autorizado resource_operation com endpoint_id/values: requer view/messages.view em leituras, protocols.manage em escrita administrativa, messages.send em envio; settings.manage para campanha/SMS/telefonia. Login separado operador pelo vínculo do usuário; scopes mínimos e diagnóstico para contrato ambíguo. Lease SQL por empresa/operador em volta de selecionar+executar, token privado no servidor, sem user/operator identidade livre. Reutilizar gateway nos sends/transfer/finalizar/assumir existentes de acordo com estado externo. Validar importação com canal e só variantes DDI; todos operadores paginados. Ledger de tentativas/notification_id/estado unknown após timeout; nunca request_id como message ID; não repetir mutações desconhecidas. Limites corretos e URL temporária, sem base64 fallback; preservar bucket existente. sync_resource/bootstrap com cursores paginados retomáveis; atualizar status em mensagens existentes e reconciliar saída externa. Enviar objetos tolerantes mas recusar JSON inválido. API devolve success,data,outcome,has_more,next_page; fornecedor recusado mantém type/erro seguro. Testar gateway com transporte fake, argumentos/ordem/erros/concorrência, sem Supabase vivo.

## Task 3: eventos e worker durável
Arquivos próprios: sac-digital-webhook/index.ts, sac-digital-worker/index.ts, _shared/sac-events.mjs/test; migration 20261007141000_sac_digital_jobs_projection.sql. Gravar evento canônico e job transacional antes ACK; waitUntil só acelera. Jobs com lease, tentativas/backoff, retomada e função SQL cron para projeção durável sem extensão nova. Oito eventos documentados, mídia antes legenda, guarda temporal no estado; SMS reply e contact_new projetados. Worker autorizado somente service_role ou segredo interno privado, processa jobs limitados e chama ações internas API (sync_protocol_history/enrich_protocol) sem mensagens. Criação de job reconciliação agregado por protocolo. Saúde consultável e retries existentes compatíveis. Testar dedupe, mensagem com legenda, ordem temporal, retomada e ACK com transporte lento.

## Task 4: interface de todos recursos
Arquivos próprios: src/features/sac-digital/presentation/*, infrastructure/sac-digital.repository.ts, domain UI helpers/tests. Consumir catálogo Task1 e resource_operation Task2 através invoke autenticado. Acrescentar áreas nomeadas humanas para contatos/recados/canais/departamentos/operadores/monitores/grupos/campanhas/etiquetas/notificações/WA/cupons/SMS/produtos/Correios/portabilidade/agendamento/carteira/telefonia/perfil/respostas rápidas/recuperação/atendimento. Navegação + seleção de recurso + formulários de campos reais e condicionais; resultados em listas/cards com mídia, paginação correta, seleção IDs ao consultar, estados vazios/erros/indisponível; jamais tela JSON/HTTP para usuário. Campanha editor conteúdo/tipos/filtros/prévia; templates/variáveis sem JSON livre. Sem botão falso de sucesso; confirmação dentro do produto para campanhas/ações destrutivas. Operações ambíguas identificadas ao falhar. Fila/history/observações/tags/groups acessíveis pelo protocolo; respostas rápidas inserem compositor. Nova conversa pode usar notification/direct com canal/template se contato ausente; não exigir CRM. Manter realtime e reconciliação bounded ativa; limites corrigidos nos três compositores; status sem falso enviada. Usar permissões existentes. Não editar arquivos Task2/3 nem package.json. Testar helpers pure e compilar pelo root final.

## Task 5: integrar e verificar
Root revisa diffs e testes de cada frente, fresh reviewer final, uma build CRM, regressões existentes. Migrações/functions somente após revisão e schema compatível; atualizar main com lease e push único. Registrar fichas implementadas/testadas/dependências externas no relatório versionado. Nenhum contrato sem evidência recebe selo produção validada.
